# Hetzner Webhosting – Fakten für die Deploy-Anleitung

Quelle: https://docs.hetzner.com/managed/administration-on-konsoleh/nodejs/ (Okt 2025)

- Node.js verfügbar ab **Webhosting L/XL**, Aktivierung in konsoleH: Domain wählen → Services → Node.js configuration → roter Button "Aktivieren".
- ACHTUNG: Beim Aktivieren von Node.js für eine Domain werden **alle anderen Webanwendungen (PHP/HTML) für diese Domain deaktiviert**.
- Konfigurierbar in konsoleH: Script path (relativ zum Working directory), Working directory (relativ zum Home), Log file, Memory limit, Version, Arguments, **Environment variables**.
- Node-Version alternativ per SSH: `echo 24 > ~/.nodeversion`; einzelne Befehle mit `NODEVERSION=22 npm install -g ...`.
- SSH ist verfügbar (eigene Software installierbar). MySQL-Datenbanken werden in konsoleH angelegt.
- Beispiel Uptime Kuma: git clone + `NODEVERSION=20 npm run setup` → zeigt, dass Build-Schritte per SSH möglich sind.
- Port: Beispiel-App ruft `server.listen()` OHNE Port auf → Hetzner gibt Port via Umgebung vor (Node wählt/Proxy davor). Unsere App nutzt `process.env.PORT || 3000` → PORT muss ggf. als Umgebungsvariable gesetzt werden oder listen ohne Port. WICHTIG in Anleitung erwähnen.

## Projektspezifisch
- Start: `pnpm build` erzeugt `dist/index.js` (esbuild, ESM) + `dist/public` (Vite). Start: `NODE_ENV=production node dist/index.js`.
- Pflicht-Env: DATABASE_URL (mysql://user:pass@host:3306/db), JWT_SECRET.
- Optional: SMTP_HOST/PORT/USER/PASS/FROM für Passwort-Reset-Mails (neu: server/mailer.ts).
- Migrationen: drizzle/0000..0006 SQL-Dateien; per `pnpm drizzle-kit migrate` oder SQL manuell einspielen.
- Alle Bilder jetzt lokal gebündelt (42 WebP in client/src/assets, dist/public/assets ~4.6 MB) → kein Manus-Storage nötig.
